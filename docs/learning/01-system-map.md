# 已学知识怎样连起来

从上电开始：芯片内的 BootROM 找到早期启动内容，早期代码初始化 DDR，U-Boot 把内核和设备树加载到内存，内核建立设备与进程管理能力，找到 rootfs，启动 PID 1，再由初始化程序启动各项服务。

| 名称 | 可以怎样理解 |
| --- | --- |
| 内核 | 管 CPU、内存、进程、网络和驱动的核心程序 |
| rootfs | 系统根目录下供程序使用的文件集合；包括程序、库、配置等 |
| ext4 | 将目录和文件组织在存储设备上的一种文件系统 |
| OverlayFS | 把已有内容和修改层合并成一个目录视图；它与 ext4 解决不同问题 |
| BusyBox | 把许多常用命令和可选的 init 实现放在一个程序里的工具集 |
| systemd | 用户空间的初始化和服务管理程序，作为系统 init 时是 PID 1 |
| GCC | 可选的用户空间编译器；把 C 等源码变成目标机器可执行的代码，不是内核能力 |
| /proc | 内核通过 procfs 提供进程和系统状态，例如 /proc/uptime |
| /sys | 内核通过 sysfs 暴露设备、驱动和内核对象属性 |
| /dev | 程序访问设备接口时常用的设备节点目录 |

`main.c` 是源码；编译后的 `edge-agent` 是可执行文件；执行它才产生进程。一个可执行文件可以同时产生多个进程。PID 是进程号，`readlink /proc/PID/exe` 查看进程关联的可执行文件路径，不是在看源代码。

设备接入的责任链：设备树描述硬件 → 总线/驱动核心匹配驱动 → 驱动 probe 初始化 → 注册输入、网络等子系统接口 → 用户程序通过系统调用使用接口。并非每个设备都有一份独占驱动文件。

epoll 属于内核提供给用户程序的 I/O 就绪通知机制。程序等待哪些文件描述符可读，再自己调用 read 取数据；它不是通用的硬件中断队列。

构建镜像则把这些关系反过来准备好：选择目标硬件和工具链，构建内核/驱动/DTB，准备用户态 rootfs 和启动规则，再按板子布局打包。生成文件、写卡成功和上电能用，是三个不同结果。
